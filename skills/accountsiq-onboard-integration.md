# Onboard onto the AccountsIQ API

**You cannot self-serve this.** There is no signup form and no instant key. Access is granted by
AccountsIQ by email. Plan for that lead time before promising a delivery date.

## 1. Get permission

Email `integration@accountsiq.com`. Two things happen there:

- You read and acknowledge the API Terms of Use. Acknowledgement is a precondition of use.
- You register your intended use and receive a **staging** partner key.

Production keys are a **separate set**. Staging servers refuse production credentials and
production servers refuse staging ones — if `TokenGet` returns nothing, this is the first thing
to check.

## 2. Get a sandbox

You need a company to work against — either a blank demo company, or a copy of a live entity.
A copy of a live entity requires **explicit permission from that customer**. Ask AccountsIQ.

## 3. Understand the two keys

- **Partner key** — identifies you, the integrator. Issued by AccountsIQ. Sensitive: you are
  contractually responsible for its use, it must not be shared, and it must not be extractable
  from your application by reverse engineering. Never ship it in client-side code.
- **User key** — generated by an end user inside their own AccountsIQ company. It lets you act
  as that user, so their permissions are your permissions.

## 4. Pick a version

- **Integration 2.0** — use this. OAuth 2.0 client credentials, 219 operations.
- **Integration 1.1** — legacy, still supported, 217 operations, `Login` session tokens valid
  20 minutes. Only for existing integrations.

## 5. Generate a client

AccountsIQ publishes **no client libraries** — it says so directly. The WSDL is the SDK.

```
https://{region}.accountsiq.com/system/dashboard/integration/integration_2_0.asmx?wsdl
```

- **C# / VB.NET** — Add Web Reference, or `wsdl.exe`. First-class; all official samples are C#.
- **PHP** — `wsdl2php` against the WSDL, pointed at staging, then `require_once` the generated
  includes and follow the C# samples.
- **Java** and anything else — any SOAP 1.1 toolchain. The service is language-independent.

The WSDL is **byte-identical across all four regions**; only the host differs. Generate the
proxy once.

Two more references worth having open:

- The ASP.NET help page at `.../integration_1_1.asmx` lists every operation with generated SOAP
  request and response samples at `?op=<OperationName>`. It reads anonymously.
- First-party Postman collections, one per region and version, live in the provider's repo.

## 6. Authenticate

`TokenGet(clientId, clientSecret)` returns `AccessToken` + `RefreshToken`.

Set both header fields on every call:

```
AiqSoapHeader:
  AccessToken: <AccessToken>
  Entity:      <entity code>
```

Leave each operation's first `token` argument **blank** on 2.0 — it exists only for 1.1
compatibility. On `HasExpired = true`, call `TokenRefresh`.

## 7. Smoke test

In order: `GetEntitiesByToken` (auth works and shows what you can reach), then
`GetCompanyInformation` and `GetCurrencies` for the entity you picked. All three are read-only.

## 8. Resetting test data

There is no reset operation. Email `integration@accountsiq.com` saying what to clear and for
which company.

## 9. Going live

1. Email `integration@accountsiq.com` for a live production partner key.
2. Repoint your web reference from staging to the production URL.
3. Collect each end user's own user integration key.
4. **Let the user choose their region.** `eu1`, `eu2`, `uk1` and `us1` are separate deployments
   and a customer's data exists in exactly one. Never hardcode a region and never infer it.

## What to expect in production

- **No rate limit** — stated by AccountsIQ. Fair-use obligations in the Terms of Use apply
  instead: do not degrade the platform's performance or stability.
- **No webhooks** — poll. See `accountsiq-incremental-sync`.
- **No idempotency** — read back before retrying a write.
- **No changelog page** — change notices go out through the SOAP API Update Bulletin mailing
  list. Subscribe, or you will not hear about new methods and fixes.
- **Errors arrive on HTTP 200** — check `Status` and `ErrorCode` on `WSResult2Of<T>` every time.
